# Zeta Overlay (개인용 스켈레톤)

제타 앱 채팅 화면 위에, 사용자가 지정한 캐릭터 이미지를 오버레이로 그려주는 개인용 프로젝트입니다.

## 화면 구조 (실측 덤프로 확인됨)
제타는 네이티브 뷰가 아니라 **WebView(웹페이지)로 채팅 화면을 그립니다.** 메시지마다 아바타+이름이
반복되는 구조인데, 다행히 접근성 트리에는 이렇게 잡힙니다:

```
android.widget.Button   text=박현우  bounds=Rect(19, 1729 - 115, 1825)   ← 아바타. 96x96 정사각형.
android.widget.TextView text=박현우  bounds=Rect(126, 1732 - 219, 1777)  ← 이름 라벨(별도 사용 안 함)
```

핵심은 **아바타 Button 자체의 `text`가 곧 캐릭터 이름**이라는 것입니다. 그래서 "아바타 옆의 이름
텍스트를 따로 찾아 매칭"할 필요 없이, "정사각형 Button + 그 Button의 text"만 보면 됩니다.
(`ImageView`가 아니라 `Button`으로 잡히는 것도 WebView라서 그런 것으로 보입니다.)

## 지금 상태
- `collectAvatarButtons`가 화면 전체에서 `Button` 노드 중 정사각형에 가깝고(96px 근처),
  text가 12자 이내인 것만 아바타로 간주하고, 그 text를 캐릭터 이름으로 바로 사용합니다.
- `ZetaAccessibilityService.DEBUG_DUMP_TREE = true`로 되어 있어서, 제타 앱을 열 때마다
  전체 화면 뷰 트리(클래스명, id, 텍스트, 좌표)를 폰 내부 파일(`zeta_dump.txt`)에 덮어써서 저장합니다.
- 오버레이 아이디는 `이름@(y좌표/30)`으로 대략 묶어서, 스크롤 중 미세한 좌표 변화로
  오버레이가 계속 재생성되는 걸 줄였습니다. 스크롤 시 깜빡임이 심하면 이 구간 크기(30)를 조정하세요.
- `AVATAR_MIN_PX`/`AVATAR_MAX_PX`(60~220)는 1080폭 기기의 96px 실측값 기준이라, 다른 해상도
  기기에서 안 맞으면 이 범위를 조정하세요.

## PC 없이 덤프 확인하기
1. 접근성 권한을 켠 상태에서 제타 채팅방을 한 번 엽니다.
2. 우리 앱(ZetaOverlay)으로 돌아와 **"마지막 화면 덤프 불러오기"**를 누르면 화면에 텍스트로 표시됩니다.
3. **"덤프 공유하기"**를 누르면 카카오톡 "나에게 보내기", 이메일 등으로 바로 보낼 수 있습니다.
4. 그 텍스트를 복사해서 개발 대화에 붙여넣으면 좌표/조건을 실측치로 다듬을 수 있습니다.

(PC와 USB로 연결 가능한 상황이라면 Logcat에서도 동일한 로그를 볼 수 있지만 필수는 아닙니다.)

## 다음에 할 일
1. 새로 빌드한 apk를 설치하고, 매핑을 등록한 캐릭터의 채팅방을 열어 오버레이가 실제로 뜨는지 확인
2. 스크롤할 때 오버레이 위치가 잘 따라오는지, 깜빡임은 없는지 확인 (심하면 `id` 구간 크기 30을 조정)
3. 다른 해상도 기기에서도 테스트한다면 `AVATAR_MIN_PX`/`AVATAR_MAX_PX` 재조정
4. 정상 동작이 확인되면 `DEBUG_DUMP_TREE`를 `false`로 바꿔서 불필요한 파일 쓰기를 끔

## 사용 흐름
1. 앱 실행 → 캐릭터 이름 입력 + 이미지 선택 → 매핑 저장
2. 설정 > 접근성에서 서비스 켜기
3. 제타 앱에서 해당 이름의 캐릭터 채팅을 열면 저장된 이미지가 오버레이로 표시됨

## 열기
Android Studio가 있다면: 이 폴더를 "Open" → Gradle sync → 기기 연결 후 Run.

## 서명 키 (업데이트 시 재설치 문제 방지)
`app/debug.keystore`를 저장소에 고정해두고 `app/build.gradle`에서 그 키로만 서명하도록 했습니다.
이게 없으면 GitHub Actions가 매번 새 서버에서 빌드할 때마다 서명이 랜덤하게 달라져서, 업데이트할
때마다 기존 앱을 지우고 재설치해야 하고(+ 저장해둔 매핑도 날아감) 하는 문제가 생깁니다. 이 키가
있으면 앞으로는 그냥 새 apk를 그 위에 설치(덮어쓰기)하면 됩니다.

## Android Studio 없이 빌드하기 (GitHub Actions)
PC 용량이 부족해서 Android Studio를 못 깔 때는, 컴파일을 GitHub 서버가 대신 하게 만들 수 있습니다.
이 프로젝트에는 `.github/workflows/build.yml`이 이미 포함되어 있어서, 저장소에 올리기만 하면 됩니다.

1. GitHub에서 새 저장소 생성 (private 추천, 이름은 자유롭게 — 예: `zeta-overlay`)
2. 이 프로젝트 폴더(zip 압축 푼 것) 전체를 그 저장소에 올립니다.
   - git이 있다면: `git init && git add . && git commit -m "init" && git branch -M main && git remote add origin <저장소 주소> && git push -u origin main`
   - git이 없다면: 저장소 페이지의 "Add file > Upload files"에서 폴더째로 드래그해서 업로드 (git 설치 불필요)
3. 저장소의 **Actions** 탭으로 이동 → "Build APK" 워크플로가 자동으로 돌아가고 있거나, 없으면 "Run workflow"로 수동 실행
4. 빌드가 끝나면(2~5분 정도) 해당 실행 결과 페이지 하단의 **Artifacts**에서 `app-debug` 다운로드 → 압축 풀면 `app-debug.apk`
5. 그 apk를 카톡/구글드라이브로 폰에 보내서 설치 (위 "PC 없이 덤프 확인하기" 이전 안내와 동일한 설치 방식)


## 알려진 버그와 수정 (오버레이가 안 지워지고, 스크롤 싱크가 안 맞던 문제)
`accessibility_service_config.xml`에서 이벤트를 제타 패키지로만 필터링해놨더니, 제타를 벗어나는
순간 우리 서비스가 아예 이벤트를 못 받아서 마지막 오버레이가 화면에 그대로 박제되는 문제가 있었고
(다른 앱 위에도 계속 떠 있음), WebView 특성상 스크롤 시 이벤트가 안정적으로 안 와서 오버레이 위치가
안 따라오는 문제도 있었습니다.

그래서 이벤트에만 의존하지 않고, 0.2초마다 스스로 화면을 다시 확인하는 폴링 방식으로 바꿨습니다
(`ZetaAccessibilityService.POLL_INTERVAL_MS`). 이러면 제타를 벗어나는 즉시 오버레이가 지워지고,
스크롤 중에도 계속 위치가 갱신됩니다.

## 추가 개선 (원형 오버레이 + 스크롤 이벤트 추가 구독)
- 오버레이를 정사각형이 아니라 **원형**으로 잘라서 보여주도록 바꿨습니다 (`OverlayManager`의
  `ViewOutlineProvider.setOval`).
- 접근성 설정에 `typeViewScrolled`도 구독하도록 추가해서, 폴링 주기(0.2초) 사이의 공백을 줄였습니다.
  다만 WebView 특성상 아주 빠른 플릭 스크롤까지 완벽하게 따라잡는 건 구조적으로 어렵습니다 —
  폴링 주기를 줄이면(`POLL_INTERVAL_MS`) 더 촘촘해지지만 배터리 소모가 늘어나는 트레이드오프가 있습니다.

## 캐릭터별 매핑 관리 화면
메인 화면의 "캐릭터별 매핑 관리" 버튼을 누르면 등록된 모든 캐릭터-이미지 매핑을 목록으로 보고,
각각 "변경"(새 이미지로 교체)/"삭제"할 수 있는 화면(`MappingListActivity`)이 열립니다.

## 오버레이 위치 어긋남 (진행 중인 이슈)
스크린샷으로 "덮어쓴 이미지가 실제 아바타보다 아래에 떠서 원본이 안 가려지고, 심하면 채팅 영역
밖으로도 나간다"는 문제가 보고됐습니다. 원인으로 의심되는 건 WebView의 접근성 트리가 실제 렌더링과
약간의 시간차를 두고 갱신되는 것 — 특히 스크롤 중에 두드러짐. 1차 완화책으로 `ZetaAccessibilityService`에
"같은 아바타 id가 직전 폴링에도 있었을 때만 그린다"는 안정화 필터를 추가했습니다 (스크롤 중 새로
나타나는 항목은 한 박자 쉬었다가, 자리가 안정되면 그때 그림). 스크롤이 아주 빠르면 여전히 잠깐
안 보이거나 밀릴 수 있습니다. 이 문제가 계속되면, 어긋난 순간에 "덤프 불러오기"로 받은 텍스트와
그 순간의 스크린샷을 같이 주시면 정확한 오차를 계산해서 고칠 수 있습니다.

## 클라우드 동기화 (Firebase) 설정 — 빌드 전 필수

캐릭터 매핑을 Firestore/Storage에 동기화하는 기능이 추가됐다. **`app/google-services.json` 파일이 없으면
빌드 자체가 실패한다** (google-services 플러그인이 강제함). 아래 순서로 준비해야 한다.

1. https://console.firebase.google.com 에서 새 프로젝트 생성
2. 프로젝트에 Android 앱 추가, 패키지명은 정확히 `com.example.zetaoverlay`
3. Authentication → Sign-in method에서 **익명(Anonymous)** 로그인 활성화
4. Firestore Database 생성 (프로덕션 모드로 시작해도 무방 — 규칙은 아래에서 따로 설정)
5. Storage 생성
6. Firestore 규칙 탭에 이 저장소의 `firestore.rules` 내용을, Storage 규칙 탭에 `storage.rules` 내용을 붙여넣고 게시
7. 앱 추가 화면에서 `google-services.json` 다운로드 → 이 프로젝트의 `app/` 폴더에 넣고 커밋
   (개인용 프로젝트라 이 파일 자체를 저장소에 커밋해도 큰 문제 없음 — 실제 접근 제어는 위 규칙이 담당)

이 파일이 준비되기 전까지는 GitHub Actions 빌드가 계속 실패한다.

### 동작 방식
- 로컬 저장(SharedPreferences + 내부 파일)은 기존과 동일하게 즉시/동기로 끝나며, 오프라인에서도 오버레이는
  정상 동작한다.
- 매핑 저장/변경 시 이미지가 `images/{uid}/{characterName}.jpg`로 Storage에 업로드되고, 성공하면 그 다운로드
  URL이 `users/{uid}/mappings/{characterName}` Firestore 문서에 기록된다.
- 매핑 삭제 시 해당 Firestore 문서도 함께 삭제된다.
- 클라우드 동기화가 실패해도(네트워크 없음 등) 로컬 기능에는 전혀 영향 없다 — 조용히 무시된다.
- 메인 화면에 앱의 UID가 표시되고 복사할 수 있다 (다른 기기에서 수동으로 대조할 때 등에 사용).
