# Zeta Overlay (개인용 스켈레톤)

제타 앱 채팅 화면 위에, 사용자가 지정한 캐릭터 이미지를 오버레이로 그려주는 개인용 프로젝트입니다.

## 화면 구조 (실측 덤프로 확인됨)
제타는 네이티브 뷰가 아니라 **WebView(웹페이지)로 채팅 화면을 그립니다.** 메시지마다 아바타+이름이
반복되는 구조인데, 다행히 접근성 트리에는 이렇게 잡힙니다:

```
android.widget.Button   text=박현우  bounds=Rect(19, 1729 - 115, 1825)   ← 아바타. 96x96 정사각형.
android.widget.TextView text=박현우  bounds=Rect(126, 1732 - 219, 1777)  ← 이름 라벨(별도 사용 안 함)
```

핵심은 **아바타 Button 자체의 `text`가 곧 캐릭터 이름**이라는 것입니다. 그래서 "아바타 옆의 이름
텍스트를 따로 찾아 매칭"할 필요 없이, "정사각형 Button + 그 Button의 text"만 보면 됩니다.
(`ImageView`가 아니라 `Button`으로 잡히는 것도 WebView라서 그런 것으로 보입니다.)

## 지금 상태
- `collectAvatarButtons`가 화면 전체에서 `Button` 노드 중 정사각형에 가깝고(96px 근처),
  text가 12자 이내인 것만 아바타로 간주하고, 그 text를 캐릭터 이름으로 바로 사용합니다.
- `ZetaAccessibilityService.DEBUG_DUMP_TREE = true`로 되어 있어서, 제타 앱을 열 때마다
  전체 화면 뷰 트리(클래스명, id, 텍스트, 좌표)를 폰 내부 파일(`zeta_dump.txt`)에 덮어써서 저장합니다.
- 오버레이 아이디는 `이름@(y좌표/30)`으로 대략 묶어서, 스크롤 중 미세한 좌표 변화로
  오버레이가 계속 재생성되는 걸 줄였습니다. 스크롤 시 깜빡임이 심하면 이 구간 크기(30)를 조정하세요.
- `AVATAR_MIN_PX`/`AVATAR_MAX_PX`(60~220)는 1080폭 기기의 96px 실측값 기준이라, 다른 해상도
  기기에서 안 맞으면 이 범위를 조정하세요.

## PC 없이 덤프 확인하기
1. 접근성 권한을 켠 상태에서 제타 채팅방을 한 번 엽니다.
2. 우리 앱(ZetaOverlay)으로 돌아와 **"마지막 화면 덤프 불러오기"**를 누르면 화면에 텍스트로 표시됩니다.
3. **"덤프 공유하기"**를 누르면 카카오톡 "나에게 보내기", 이메일 등으로 바로 보낼 수 있습니다.
4. 그 텍스트를 복사해서 개발 대화에 붙여넣으면 좌표/조건을 실측치로 다듬을 수 있습니다.

(PC와 USB로 연결 가능한 상황이라면 Logcat에서도 동일한 로그를 볼 수 있지만 필수는 아닙니다.)

## 다음에 할 일
1. 새로 빌드한 apk를 설치하고, 매핑을 등록한 캐릭터의 채팅방을 열어 오버레이가 실제로 뜨는지 확인
2. 스크롤할 때 오버레이 위치가 잘 따라오는지, 깜빡임은 없는지 확인 (심하면 `id` 구간 크기 30을 조정)
3. 다른 해상도 기기에서도 테스트한다면 `AVATAR_MIN_PX`/`AVATAR_MAX_PX` 재조정
4. 정상 동작이 확인되면 `DEBUG_DUMP_TREE`를 `false`로 바꿔서 불필요한 파일 쓰기를 끔

## 사용 흐름
1. 앱 실행 → 캐릭터 이름 입력 + 이미지 선택 → 매핑 저장
2. 설정 > 접근성에서 서비스 켜기
3. 제타 앱에서 해당 이름의 캐릭터 채팅을 열면 저장된 이미지가 오버레이로 표시됨

## 열기
Android Studio가 있다면: 이 폴더를 "Open" → Gradle sync → 기기 연결 후 Run.

## Android Studio 없이 빌드하기 (GitHub Actions)
PC 용량이 부족해서 Android Studio를 못 깔 때는, 컴파일을 GitHub 서버가 대신 하게 만들 수 있습니다.
이 프로젝트에는 `.github/workflows/build.yml`이 이미 포함되어 있어서, 저장소에 올리기만 하면 됩니다.

1. GitHub에서 새 저장소 생성 (private 추천, 이름은 자유롭게 — 예: `zeta-overlay`)
2. 이 프로젝트 폴더(zip 압축 푼 것) 전체를 그 저장소에 올립니다.
   - git이 있다면: `git init && git add . && git commit -m "init" && git branch -M main && git remote add origin <저장소 주소> && git push -u origin main`
   - git이 없다면: 저장소 페이지의 "Add file > Upload files"에서 폴더째로 드래그해서 업로드 (git 설치 불필요)
3. 저장소의 **Actions** 탭으로 이동 → "Build APK" 워크플로가 자동으로 돌아가고 있거나, 없으면 "Run workflow"로 수동 실행
4. 빌드가 끝나면(2~5분 정도) 해당 실행 결과 페이지 하단의 **Artifacts**에서 `app-debug` 다운로드 → 압축 풀면 `app-debug.apk`
5. 그 apk를 카톡/구글드라이브로 폰에 보내서 설치 (위 "PC 없이 덤프 확인하기" 이전 안내와 동일한 설치 방식)
